# Команда /auth

## Алгоритм

```plantuml
@startuml
participant "Клиент" as C
participant "Текущее API" as A
database "БД" as DB
participant "UserStateStorage" as UserStateStorage
participant "Сайт donor-mos*" as S

== Этап 1: Инициализация ==

C -> A: /auth
A -> DB: Найти пользователя (chatId)
DB --> A: User
A -> A: Определить выбранный сайт
A -> UserStateStorage: Установить состояние AWAITING_AUTH_CREDENTIALS
A -> C: Отправить форму авторизации

== Этап 2: Ввод credentials ==

C -> A: "email password"
A -> A: Проверить состояние AWAITING_AUTH_CREDENTIALS
A -> A: Разбить на username и password

== Этап 3: Валидация на сайте ==

alt Выбран конкретный сайт
    A -> S: GET /login (сбор cookies)
    S --> A: Cookies + HTML
    A -> A: Извлечь JS cookies из HTML
    A -> S: GET redirect URL (сбор cookies)
    S --> A: Дополнительные cookies
    A -> S: POST /auth (log, pwd, redirect_to)
    S --> A: Auth cookies
    A -> S: GET /account (проверка авторизации)
    S --> A: HTML страницы аккаунта
    
    alt Страница содержит "table-item__date"
        A -> A: Авторизация успешна
    else Сайт недоступен
        A -> C: Отправить ошибку "Сайт недоступен"
    else Неверные credentials
        A -> C: Отправить ошибку авторизации
    end
else Выбран ALL
    A -> A: Получить список сайтов: [DONOR_MOS, DONOR_MOS_SAB, DONOR_MOS_ZAR]
    loop Для каждого сайта
        A -> S: GET /login (сбор cookies)
        S --> A: Cookies + HTML
        A -> A: Извлечь JS cookies из HTML
        A -> S: GET redirect URL (сбор cookies)
        S --> A: Дополнительные cookies
        A -> S: POST /auth (log, pwd, redirect_to)
        S --> A: Auth cookies
        A -> S: GET /account (проверка авторизации)
        S --> A: HTML страницы аккаунта
        
        alt Страница содержит "table-item__date"
            A -> A: Авторизация успешна (прерываем цикл)
        else Неверные credentials
            A -> A: Пометить сайт как "auth failed"
        else Сайт недоступен / сетевая ошибка
            A -> A: Пометить сайт как "unavailable"
        end
    end
    
    alt Хотя бы 1 сайт успешен
        A -> A: Авторизация успешна
    else Все сайты вернули "auth failed"
        A -> C: Отправить ошибку авторизации
    else Все сайты недоступны / сетевые ошибки
        A -> C: Отправить ошибку "Сайты недоступны"
    end
end

== Этап 4: Сохранение и переход ==

alt Авторизация успешна
    A -> DB: Сохранить пользователя (email, encrypted password)
    A -> UserStateStorage: Очистить состояние
    A -> A: Вызвать /main
    A -> C: Отправить главное меню
end
@enduml
```

## Детальное описание алгоритма

### Этап 1: Инициализация

1. **Получение команды** — пользователь отправляет команду `/auth`
2. **Поиск пользователя** — система ищет пользователя в БД по `chatId`
3. **Определение сайта** — если у пользователя выбран сайт `ALL`, отображается "всех центров крови", иначе — конкретный URL сайта
4. **Установка состояния** — в `UserStateStorage` устанавливается состояние `AWAITING_AUTH_CREDENTIALS`
5. **Отправка формы** — пользователю отправляется меню с просьбой ввести credentials в формате: `логин пароль`

### Этап 2: Ввод credentials

1. **Получение сообщения** — пользователь отправляет сообщение в формате `email password`
2. **Проверка состояния** — `AuthUpdateHandler` проверяет, что пользователь находится в состоянии `AWAITING_AUTH_CREDENTIALS`
3. **Парсинг** — сообщение разбивается на две части: `username` (email) и `password`

### Этап 3: Валидация на сайте

Процесс валидации выполняется через `AuthService.isCredentialValid()`:

#### Вариант А: Выбран конкретный сайт

1. **Определение сайта** — берётся сайт пользователя из БД
2. **Preflight сбор cookies** (`preflightCollectCookies`):
   - GET запрос на страницу логина — сбор `Set-Cookie` заголовков
   - Извлечение JS-куки из HTML (если есть)
   - Переход по JS-редиректу (если есть) — сбор дополнительных cookies
   - Повторный GET на страницу логина — финальный сбор cookies
3. **Отправка авторизации**:
   - POST запрос на `/auth` с параметрами: `log`, `pwd`, `redirect_to`
   - Сбор авторизационных cookies из ответа
4. **Проверка успешности**:
   - GET запрос на страницу аккаунта с собранными cookies
   - Проверка наличия элемента `table-item__date` в HTML
   - Если элемент найден — авторизация успешна

#### Вариант Б: Выбран ALL

1. **Получение списка сайтов** — через `UserSite.getIndividualSites()` получаем: `[DONOR_MOS, DONOR_MOS_SAB, DONOR_MOS_ZAR]`
2. **Цикл по сайтам** — для каждого сайта выполняется полный процесс авторизации (preflight → POST → проверка аккаунта)
3. **Накопление результатов**:
   - **Успех** — если хотя бы на одном сайте найден `table-item__date`, авторизация считается успешной, цикл прерывается
   - **AuthFailed** — если сайт доступен, но креды неверны (нет cookies или нет `table-item__date`)
   - **SiteUnavailable** — если сайт вернул сетевую ошибку, 4xx/5xx или не отвечает после retry
4. **Итоговая проверка**:
   - Хоть 1 успех → `return true`
   - Все сайты вернули `AuthFailedException` → `return false` (неверные креды)
   - Все сайты вернули `SiteUnavailableException` → пробрасываем `SiteUnavailableException`

#### Retry механизм

- При ошибках сети (`RestClientException`) выполняется до `maxAttempts` попыток
- Задержка между попытками: `delayMs` миллисекунд
- После исчерпания попыток выбрасывается `SiteUnavailableException`
- `AuthFailedException` не retry-ится — сразу прерывает попытки

### Этап 4: Сохранение и переход

При успешной авторизации:

1. **Шифрование пароля** — пароль шифруется через `EncryptionUtils.encrypt()` с использованием секретного ключа
2. **Сохранение пользователя** — в БД сохраняется:
   - `id` — chatId
   - `email` — логин
   - `password` — зашифрованный пароль
   - `active` — true
   - `site` — выбранный сайт (если не был установлен)
3. **Очистка состояния** — `UserStateStorage.clearState()`
4. **Переход в главное меню** — вызов `/main`

### Обработка ошибок

| Ошибка | Условие | Действие |
|--------|---------|----------|
| `SiteUnavailableException` | Конкретный сайт недоступен после retry ИЛИ при ALL — все сайты недоступны | Отправка меню `siteUnavailable` с названием сайта (для ALL — общее сообщение) |
| `AuthFailedException` | Неверные credentials на конкретном сайте | При ALL: накопление, если все сайты — `return false`. При конкретном — `return false` |
| Неверный формат сообщения | Не 2 части после split | Отправка меню `authError` |
| Внутренняя ошибка | Непредвиденное исключение | Отправка сообщения "⚠️ Произошла внутренняя ошибка. Попробуйте позже." |

### Логика ALL: матрица результатов

| DONOR_MOS | DONOR_MOS_SAB | DONOR_MOS_ZAR | Итог |
|-----------|---------------|---------------|------|
| ✅ Успех | — | — | ✅ Авторизация успешна |
| ❌ Креды | ✅ Успех | — | ✅ Авторизация успешна |
| ❌ Креды | ❌ Креды | ❌ Креды | ❌ Ошибка авторизации |
| ❌ Креды | 🚫 Недоступен | ✅ Успех | ✅ Авторизация успешна |
| 🚫 Недоступен | 🚫 Недоступен | 🚫 Недоступен | 🚫 Сайты недоступны |
| ❌ Креды | 🚫 Недоступен | 🚫 Недоступен | ❌ Ошибка авторизации |

**Легенда:**
- ✅ Успех — найден `table-item__date`
- ❌ Креды — сайт доступен, но креды неверны
- 🚫 Недоступен — сетевая ошибка / 4xx / 5xx после retry

## Входные параметры

### Этап 1: Команда /auth

| Параметр | Тип | Источник | Описание |
|----------|-----|----------|----------|
| chatId | Long | Telegram Update | Идентификатор чата пользователя |
| update | Update | Telegram API | Объект обновления от Telegram |

### Этап 2: Ввод credentials

| Параметр | Тип | Источник | Описание |
|----------|-----|----------|----------|
| message | String | Telegram Update | Сообщение в формате "email password" |
| username | String | Парсинг сообщения | Email пользователя |
| password | String | Парсинг сообщения | Пароль в открытом виде |

## Выходные параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| Сообщение | SendMessage | Главное меню ИЛИ ошибка авторизации |
| Состояние | UserState | Очищено при успехе |
| Данные в БД | User | Сохранённый пользователь с зашифрованным паролем |

## Конфигурация

| Параметр | Описание |
|----------|----------|
| `auth-retry.max-attempts` | Количество попыток при ошибках сети |
| `auth-retry.delay-ms` | Задержка между попытками в миллисекундах |
| `encryption.secret-key` | Ключ для шифрования паролей |
